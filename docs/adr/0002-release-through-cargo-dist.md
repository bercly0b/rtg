# Release through cargo-dist

With TDLib linked statically (ROZ-185), RTG ships as a single binary, which removes the reason ADR-0001 rejected cargo-dist: its installer and Homebrew formula could not carry `libtdjson`. cargo-dist now owns the release workflow, the release installer, the Homebrew tap and the self-update mechanism, and we adopt its defaults instead of re-implementing them by hand.

## Consequences

- `release.yml` is generated by `dist` and is not edited by hand; build customisation (libc++ from apt, runners, release builds on pull requests) lives in the dist config.
- cargo-dist names the app after the package, so the package is renamed to `rtg-tui` (the binary stays `rtg`) before the first dist release. This fixes the installer name, the install-dir override `RTG_TUI_INSTALL_DIR` and the install receipt under `~/.config/rtg-tui/`; renaming later would break self-update for existing installs.
- The release installer installs to dist's default `~/.cargo/bin`, the same directory `cargo install` uses; the install receipt is what tells these two install channels apart.
- `rtg update` is built on the `axoupdater` crate, which reads the receipt and re-runs the installer.
- Linux builds run on Ubuntu 24.04: the prebuilt static TDLib from tdlib-rs needs glibc 2.38+ and libc++ 18, so an older runner fails to link and never lowered the glibc baseline anyway.
- The release installer does not install or mention libc++ on Linux; the README does.
