# Naming

How to name the project in texts that introduce it.

## Rule

The first mention of RTG on a standalone surface has "Telegram TUI" or
"Telegram client" next to it. A standalone surface is a heading, a description
or the first line of a text that is read or indexed apart from the rest: a
README, a repository description, a package description, an announcement.

After that first mention, the same text says just "RTG". Running text in
`docs/`, `GLOSSARY.md` and code comments is not a standalone surface.

## Why

The name "rtg" is shared with many unrelated projects (RealTimeGenomics'
rtg-tools and rtg-core, RTG-SLAM, thousands of repositories), so search engines
do not connect a bare "RTG" with Telegram.

## Wording

- Short: `RTG — Telegram TUI client`
- Long: `RTG — a fast Telegram TUI client for the terminal, written in Rust`

A surface with its own limits or style may change everything except the
required pair: "RTG" together with "Telegram TUI" or "Telegram client".

## Surfaces

| Surface | Where the text comes from |
| --- | --- |
| README heading and intro | `README.md`, `README.ru.md` |
| crates.io package description | `description` in `Cargo.toml` |
| Homebrew formula `desc` | generated by cargo-dist from `description` in `Cargo.toml`; not edited by hand |
| `rtg --help` | `about` in `src/cli.rs` |
| About of `bercly0b/rtg` | repository settings (`gh repo edit --description`) |
| About of `bercly0b/homebrew-rtg` | repository settings (`gh repo edit --description`) |
| Announcements and catalogue submissions | written per case, following the rule above |

GitHub release titles are an exception and stay as `<version> - <date>`: the
title is the heading of the version's section in `CHANGELOG.md`, which dist
parses to find the release notes (see [RELEASES.md](RELEASES.md)).
